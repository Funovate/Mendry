**Availability: preview**

Start by connecting a production monitoring signal to a project and inspecting
its incident evidence, diagnosis, and proposed next steps. The current journey
is intended for source evaluation.

## Prepare the incident application

The current source-evaluation journey runs the incident web application from
this repository. It requires PostgreSQL for business data, Redis for login
sessions, a bootstrapped administrator account, and project configuration.
Those are incident-application prerequisites, not dependencies of the neutral
Harness contracts.

1. Confirm the [incident application prerequisites](/docs/get-started/prerequisites/).
2. Read the [installation status](/docs/get-started/install/) before choosing an environment.
3. Run migrations and [bootstrap the administrator](/docs/get-started/bootstrap/).
4. Create and configure the [first project](/docs/get-started/first-project/).
5. Send a supported signal and inspect the [first incident](/docs/get-started/first-incident/).

This path is suitable for evaluation and development validation, not a supported
customer installation.

## For developers: Local Agent Harness

The separate Local path targets a JSON event executed through the shared Harness,
with inspectable state and no PostgreSQL, Redis, or account requirement. Its
complete walkthrough has not yet been validated for publication. See
[Local walkthrough status](/docs/get-started/local-harness/). This development
path has different prerequisites and readiness from the incident application.

## Extend from source

Read [Extend the Harness](/docs/guides/extending-harness/) for the implemented
tool, policy, Profile, evaluator, artifact, and `RunStore` contracts. That guide
documents source APIs; it is not a claim that a public SDK or generic service UI
has shipped.
